# Tasks

Preparing a **new library** is one config:

```yaml
tasks: ['build_synthon_id_index', 'group_synthon_data', 'generate_synthon_conformers']
```

A run executes the `tasks:` listed in the config, **in pipeline order** rather than the order
you write them — so `['write_product_poses', 'score_synthons']` still scores first. Task names
map one-to-one onto modules in `sass/tasks/`, and an unrecognized name is an error rather than a
silent no-op.

### Valid tasks:

- **build_synthon_id_index**: Build the string -> integer synthon id index for a new library.
  Step one of preparing a library; the other library tasks read the index it writes.
  - input: the raw synthon file, plus `synthon_id_index` naming where to write.
  - output: `synthon_id_index.pkl`, a `list[str]` whose position *is* the integer id.
  - The index is a pure function of the id set -- sorted before numbering -- so rebuilding it
    from the same synthon file is byte-identical regardless of row order. That matters: a
    different numbering would silently change what every conformer title in the library means.

- **group_synthon_data**: Pre-process synthon data into `grouped_synthons.pkl` and `synthon_data.pkl`.

- **enumerate_full_library**: Exhaustively enumerate the chemical space defined by the input synthons.
  - input: Reaction and synthon files.
  - output: Molecule file(s) in `oeb.gz` format.

- **generate_full_library_conformers**: Generate conformers of the enumerated library using OMEGA. The parameters for OMEGA are defined in the config file.
  - input: molecule files.
  - output: conformer files in `oez` format.

- **score_full_library**: Score the conformer database against a given query molecule using ROCS.
  - input: conformer files; query molecule.
  - output: score list written to file (`pkl`).

- **generate_synthon_conformers**: Generate conformers of the synthons, which is different from generating conformers for full-products, because the former involves forming minimal products, conformation sampling, and restoring original connector atoms.
  - input: synthon SMILES.
  - output: conformer files in `oez` format.

- **score_synthons**: Score synthons against query fragments (using ROCS), aggregate individual synthon scores to generate pseudo-product scores, combine the `top_m` pseudo-products from different reactions. Each `dask` worker processes the content of one `fragment_order` and does synthon scoring and score aggregation. Scores from all `fragment_orders` are then merged into one file.
  - input: synthon conformers; query fragments.
  - output: combined pseudo-product file for all reactions.
  - NOTE: conceptually, synthon scores are organized in the following hierarchy. A valid product can be formed by the combining one synthon from each of the `synthon_set`s under one `fragment_order`.
    ```
    {
        rxn_id1: {
            fragment_set1: {
                fragment_order1: {
                    synthon_set1: [score1, score2, score3 ...],
                    synthon_set2: [...],
                    ...
                },
                ...
            },
            ...
        },
        ...
    }
    ```

      - `rxn_id`: Each reaction in the chemical space.
      - `fragment_set`: Each valid fragment set generated by fragmenting the query.
      - `fragment_order`: Usually there are multiple ways to order a fragment set to score against a set of `synthon_set`s. All valid orders of scoring are considered.
      - `synthon_set`: A set of synthons belonging to the same component of a multi-component reaction.

- **instantiate_products**: Instantiate the top pseudo-products. This step cannot be combined with the `rescore_products` step, because `rescore_products` already includes `instantiate_products`. This task is used when the user just wants the instantiated `top_m` pseudo products and does not need the ROCS scores of those products.
  - input: Pseudo-products file.
  - output: Molecule file(s).
  
- **rescore_products**: Instantiate the top pseudo-products, generate conformers of the instantiated products, score conformers against a given query molecule using ROCS. Scores from all chunks are merged into one file (`num_final_list` products/scores are kept).
  - input: Pseudo-products file, query molecule.
  - output: ROCS scores of full products saved to file. Conformers are **not** kept. `write_product_poses` regenerates the ones it needs.

- **write_product_poses**: Score top re-scored products against a query molecule using ROCS and write out the best overlay poses for visualization. Note that the `rescore_products` step itself only outputs the numerical scores and product ids, not the poses.
  - input: The combined rescore result file (product ids and scores), query molecule.
  - output: An SDF file containing the query molecule and best overlay poses of top products.

- **generate_single_fragment_conformers**: "Generate" appropriate synthon conformers for single-fragment searches. Instead of generating conformers from scratch, it **re-uses** conformers from `generate_synthon_conformers` (i.e. you need to have generated regular synthon conformers first and provide the path to those conformers). If `align_on_bond` option is `true`, it places additional dummy atoms along the existing dummy bond axis. Chunking is done automatically (currently hardcoded at 300 mols/chunk) to facilitate parallelization during the `score_single_fragments` step.

- **score_single_fragments**: Score synthons against a fragment query (with a pre-defined connection point). This mode searches through the synthon library once and does not do re-scoring. Currently, it treats all connector atoms (e.g. U, Np) as the same, and is only suitable for scoring fragments generated from cleaving acyclic bonds and contains only one connector atom (U).
  - input: Query fragment, single-fragment synthon conformers.
  - output: Synthon score list.

- **write_single_fragment_poses**: Retrieve the poses of the top-scoring synthons. Note that `score_single_fragments` step only outputs the numerical scores, not the poses.
  - input: Query fragment, synthon conformers, top synthon list.
  - output: Top synthon poses.


## Modes

- **Regular SASS query**: Combinatorial search in unenumerable chemical space. Run the following tasks: `score_synthons`, `rescore_products`, `write_product_poses`. If synthon conformers have not been pre-generated, run `generate_synthon_conformers` first. If intending to re-score using a different metric (i.e. not using ROCS), run just `score_synthons` and `instantiate_products` to obtain the `top_m` instantiated products. If comparing to the ground truth, only `score_synthons` is needed, as the combined pseudo-product scores can be used directly to calculate the recall.

- **Single-fragment query**: Search for synthons with high ROCS similarity to a specific query fragment. Run `score_single_fragments` and `write_single_fragment_poses`. Currently supports only one connector on the input query fragment. Requires "single-fragment conformers" generated from `generate_single_fragment_conformers`. 
  
- **Full library enumeration and search**: Enumerate the full library and score. Usually used for generating the ground truth for evaluation of top hits recovery. Run the following tasks: `enumerate_full_library`, `generate_full_library_conformers`, `score_full_library`.
